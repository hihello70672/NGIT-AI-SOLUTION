# Administration interface

`services.api.modules.admin.api.create_admin_router(service, current_user)` builds the administrative REST router. Its dependency must be the authenticated server-side `AuthContext`; identity and roles are never accepted from request bodies. `AdminService` relies on the existing `PolicyEngine`, `RestrictedActionManager`, transaction-local database caller identity and audit persistence.

Routes cover user/role/model-provider/knowledge listings, learning and report views, rules, service controls, analytics, audit events and emergency stop/reset. User and service mutations are exact-resource approval-gated. Admin rules and service intent are stored under migration `0006_admin_control.sql` with RLS. New actions are registered only after rule persistence; unknown actions deny by default.

Learning requests and reports currently reuse audit records because the schema contains no dedicated tables. Service controls persist desired state; deployment-specific executors remain outside this module. The existing approval, stop-state and permission objects are process-local, so run one API worker until shared persistence is implemented. Apply ordered migrations before enabling these endpoints; database grants and RLS need deployment-specific validation. Tests are in `services/api/tests/test_admin.py`, and SQL coverage is in `services/api/db/tests/test_schema.sql`.
